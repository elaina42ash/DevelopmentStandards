## UI 对象命名与层级规则

1. **中文命名。** UI GameObject 的业务名称统一使用中文，清楚表达用途。方括号内保留 Unity 默认创建名称，例如 `Text (TMP)`、`Image`、`Button`。
2. **默认 UI 对象格式。** 使用 Unity uGUI 默认 UI 组件创建的对象，统一命名为 `[默认创建名称]静态_中文用途` 或 `[默认创建名称]动态_中文用途`，方括号前不得添加其他名称。
3. **静态的含义。** 直接使用组件中配置的文字、图片或其他业务内容，代码不根据业务数据重新赋值。
4. **动态的含义。** 文字、图片、数值等业务内容由代码根据账号、配置、记录或运行状态赋值、更新。即使只在初始化时赋值一次，也属于动态。
5. **按内容判断。** 静态、动态不表示对象是在编辑器中创建还是运行时创建。按钮可点击、默认悬停变色、布局自动调整，不单独作为“动态”的判断依据。
6. **父子对象分别判断。** 每个对象按自身职责命名。例如入口按钮内容固定，可以标为静态；它下面显示当前风格名称的文本，由代码更新，应标为动态。
7. **自定义容器。** 页面、业务容器、列表内容节点等自定义对象使用中文业务名称，例如 `设置页面`、`记录列表内容`，不机械套用默认组件前缀。其中，仅承担区域归类整理的容器，按照“UI 区域 Root 分组约定”使用 `中文区域用途Root` 命名。
8. **适用范围与保护。** 新创建的 UI 对象遵守本规范。已有对象改名仍须遵守现有变更授权，并检查代码路径、动画和引用影响。这条规则针对 UI GameObject，C# 类型、字段和方法继续遵守代码命名规范。Prefab 资产文件和根节点的命名按照[Unity Prefab 职责与封装规范](Prefab.md)执行。

命名示例：

```text
[Text (TMP)]静态_隐私政策标题
[Text (TMP)]动态_当前风格名称
[Image]静态_区域背景
[Image]动态_用户头像
[Button]静态_隐私政策入口
[Slider]动态_总音量
```

## UI 区域 Root 分组约定

1. **面板按照实际区域语义组织层级。** 搭建面板时，应先划分具有明确用途的区域，再将对应控件归入区域容器，形成清晰的树状结构。区域内部存在进一步归类需要时，可以继续嵌套子区域容器。

2. **纯归类容器统一使用 `中文区域用途Root` 命名。** 中文部分表达区域用途，`Root` 为固定后缀，例如 `顶部区域Root`、`内容区域Root`、`音量设置Root`。此类容器不使用默认 UI 组件前缀，也不添加“静态”或“动态”标记；其子控件仍分别遵守原有命名规则。

3. **Root 表达区域归类职责。** 只有承担区域归类整理的中间容器才使用该后缀。页面根对象、具体控件、具有独立身份的业务对象，以及框架规定用途的节点，继续按照自身职责和既有契约命名，不因具有子对象就机械添加 Root。

4. **Root 本身不承担业务逻辑。** 它负责组织和承载区域下的对象，不负责业务规则、权威状态维护、用户交互协调或状态判断，也不因新增一个 Root 就配套创建 Controller、Module 或其他业务脚本。布局组件按实际布局需要和项目现有方式使用。

5. **嵌套必须具有明确的归类意义。** 每一层 Root 都应能够说明所整理的区域及内容，不为增加树的层数而重复包裹，也不要求给每个叶子控件分别增加一层 Root。

6. **Root 可以作为整组表现控制的目标。** 后续可以由 Controller 或 View 根据明确的展示状态控制区域整体显隐，Root 自身不主动决定业务状态。建立 Root 分组不代表同时授权新增显隐、置灰、交互锁定或其他状态控制逻辑；具体变更仍须遵守[UI 与交互变更授权规范](../Governance/UIChangeAuthorization.md)。

7. **既有 UI 结构继续受变更授权保护。** 本约定用于已经确认的新建 UI 或层级整理任务，不授权自动修改已有对象名称、增加包裹节点、调整父子关系、迁移组件或重新绑定引用。修改已有结构前，仍须说明布局、动画、代码路径和引用影响，并取得用户确认。

层级示例：

```text
设置页面
├─ 顶部区域Root
│  ├─ [Text (TMP)]静态_页面标题
│  └─ [Button]静态_关闭
├─ 内容区域Root
│  └─ 音量设置Root
│     ├─ [Text (TMP)]静态_音量标题
│     └─ [Slider]动态_总音量
└─ 底部操作Root
   └─ [Button]静态_确认
```
